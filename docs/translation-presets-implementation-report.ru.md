# Пресеты перевода и фрагменты 300 мс

Дата: 7 сентября 2026 года. Ветка обоих репозиториев: `feature/improve-bloadcast-delay`.

## Поведение

В панели владельца broadcast добавлен select пресетов. Новые сессии используют «Баланс». Настройки применяются кнопкой Apply ко всем языкам текущей сессии. В режиме «Вручную» показываются два подробных select, выровненные в одну строку, включая мобильную ширину 320 px.

| Пресет | Максимальная очередь переведённого аудио | Длительность входного фрагмента |
| --- | --- | --- |
| Баланс (по умолчанию) | 2 с | 100 мс |
| Лучшая скорость | 1 с | 50 мс |
| Лучшее качество | 5 с | 100 мс |
| Плохое соединение | 3 с | 300 мс |
| Вручную | 1 / 2 / 3 / 5 с | 50 / 100 / 200 / 300 мс |

«Лучшее качество» даёт очереди больше места до пропуска речи; модель и её точность этот пресет не меняет. «Плохое соединение» уменьшает число сообщений сервер → Gemini за счёт дополнительного накопления входного аудио; устранение обрывов и улучшение сети слушателя не гарантируются. Значения пресетов выбраны как настройки поведения, сравнительный выигрыш на плохой сети не измерялся.

Пометки standard/experimental у вариантов длительности удалены. Обновлены английские и чешские строки.

## Контракт и совместимость

В снимке настроек сохраняется `preset`. Переключение только режима тоже увеличивает `version`, даже если числа остались прежними. Явный ручной режим сохраняется после обновления страницы и не превращается в пресет из-за совпадения чисел. Время жизни настроек совпадает со временем жизни сессии; перезапуск сервера сбрасывает сессии.

Сервер проверяет соответствие чисел выбранному пресету, права владельца и `expectedVersion`. Прежние клиенты могут отправлять два числовых параметра без `preset`: такой запрос сохраняется как ручная настройка. До обновления серверной части новый клиент сохраняет доступ к прежним ручным настройкам и не предлагает неподдерживаемые сервером пресеты или 300 мс.

Защита входной очереди от отставания остаётся 500 мс. Непрерывный поток с фрагментами 300 мс проходит этот предел при своевременной обработке; накопление более длинного пакета оставляет меньше запаса на задержки.

## Проверка

- Сервер: 52 теста, проверка типов, форматирование, production-сборка.
- Клиент: 12 тестов, ESLint, проверка типов, форматирование, production-сборка.
- Реальная production-сборка браузера → Next API proxy → локальный Nest API: сохранение всех четырёх пресетов, ручного режима с теми же числами, ручных 300 мс и восстановление после перезагрузки.
- Новый клиент с настоящей предыдущей версией API (`ae28129`): неподдерживаемые пресеты отключены, 300 мс не предлагаются, ручные 200 мс успешно сохраняются; ошибок браузера нет.
- Все варианты длительности проходят проверку схем; значения, не соответствующие пресету, отклоняются. Проверены конфликты версий, старые запросы без пресета, применение к активным мостам и наследование настроек новыми мостами.
- Поток PCM сохраняет все сэмплы при переключениях, включая 300 мс; 300 мс формируют пакеты 9600 байт при PCM16/16 kHz и укладываются в бюджет возраста входа.
- Select выровнены на 1280, 390 и 320 px без горизонтальной прокрутки; проверены EN/CS, ошибок браузера нет.
